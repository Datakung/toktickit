## My Reflection

My prompts became more effective when I stated the current Issue boundary, existing behavior that must not regress, and the exact evidence needed before completion. A broad first decomposition hid overlapping Attachment scope and an incomplete release gate, so I requested a critical audit and rejected the original boundaries; I also corrected drafted behavior when it conflicted with persisted ordering or PostgreSQL/Prisma behavior. Peer review and fresh-database/browser tests exposed navigation, history, numeric boundaries, fixture cleanup, database isolation, advisory-lock typing, parallel-test assumptions, PostgreSQL `ILIKE` wildcard semantics, stale-process reuse, and cross-origin filename visibility that the initial output missed, which I reproduced and converted into explicit guards and regressions rather than treating AI output or an initial green run as proof of correctness.
