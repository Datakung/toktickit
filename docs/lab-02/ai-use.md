## My Reflection

My prompts became more effective when I stated the current Issue boundary, existing behavior that must not regress, and the exact evidence needed before completion. A broad first decomposition hid overlapping Attachment scope and an incomplete release gate, so I requested a critical audit and rejected the original boundaries; I also corrected drafted behavior when it conflicted with persisted ordering or PostgreSQL/Prisma behavior. Peer review and fresh-database/browser tests exposed navigation, history, numeric boundaries, fixture cleanup, database isolation, advisory-lock typing, parallel-test assumptions, PostgreSQL `ILIKE` wildcard semantics, stale-process reuse, cross-origin filename visibility, Requester reset handling, keyboard focus gaps, misleading hidden-element selectors, and stale responsive evidence that the initial output missed. I reproduced each issue and converted it into a focused guard, regression, or evidence correction instead of treating AI output, a single green run, or an old screenshot as proof of correctness.
